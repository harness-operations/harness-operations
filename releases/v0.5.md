# Harness Operations Reference Model 0.5

Reference Model 0.5 expands Code Mode prior art and clarifies tool discovery, invocation exposure, and execution authority.

## Added and clarified

- Revision-pinned Codex code-mode tool adaptation, with configuration and maturity qualifications.
- Pi's built-in MCP/QuickJS integration: automatic exposure of existing MCP tools to code mode, not conversion of the MCP server or replacement of the protocol.
- OpenAI API programmatic tool calling, explicitly separate from Codex.
- Direct model declarations, discovery, and programmatic callability distinguished from downstream authority.
- Pi's nested-call correlation, structured error results, and bounded evidence used as qualified operational examples.
- Decision-model composition linked to the existing model-informed decisions pattern; typed classifier output is not authority or enforcement.
- Comparison review questions covering prohibited invocation paths and partial outcomes without changing product findings.
- Canonical headings and status lines without post-version or unreleased qualifiers; release history stays in Git and release notes.

## Evidence and scope

These are documentation- and source-backed additions, not live Codex/Pi/API compatibility results. Existing comparison observations, evidence dates, and findings are unchanged. Release verification reruns the repository's comparison validator, applied handoff example, and exact-version interface smoke checks; those checks do not establish new Code Mode interoperability claims.

No new protocol, conformance program, runtime requirement, or universal sandboxing, approval, performance, replay, or exactly-once guarantee is introduced.
